# Release v14.3.2

## Fix — Migrations ran in parallel and the version was stamped too early

World migrations were all fired at once instead of sequentially: the version sort had no effect on execution order, and the system version was recorded before any migration had actually finished. A world interrupted mid-migration was permanently stamped as up to date and never replayed the missing migrations. Document updates inside a migration were not awaited either.

- Migrations now run one after another, in version order, and the system version is only stamped once they have all completed.
- If a migration fails, the version is not stamped at all, so the world replays it on the next load.
- The system now waits for declared migrations to finish before running the follow-up feat-format migration, instead of letting them race.
- Covered by new tests for the ordering, the version stamping and the failure case.

Thanks to badaz for the fix.
